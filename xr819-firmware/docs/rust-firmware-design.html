XR819 firmware: a Rust ownership design over the decoded DTCM map

Status draft after slices A.105–A.121 (bookmark xr819-open-firmware, ELF cec5f4be…). Scope: turn the completed reverse-engineered DTCM layout into a deliberate Rust firmware design that keeps global state in DTCM only where reentrancy forces it, and moves everything else onto owned, stack-based data.

Verdict: yes for building the ownership and module design; no for claiming writer closure. The design below therefore treats DTCM cells as shared mutable hardware-facing state with explicit access disciplines, never as immutable constants.

2. Design principles

  1. Stack first. Function-local values own computation results. DTCM holds only (a) loader-COPY images, (b) state reachable from IRQ/FIQ/HIF reentrant entry points, (c) DMA/hardware-visible buffers.
  2. One root, one gatekeeper. All DTCM addressing lives in dtcm.rs. No other module spells an address constant or builds a raw pointer. This is already the de-facto rule; make it enforced by a lint-style checker (extend the existing drift-gate tooling).
  3. Checked handles, not pointers. DtcmAddress stays the only address type. Field-level access goes through typed cell handles (section 4) rather than *mut escapes; every existing *mut accessor becomes private to dtcm.rs.
  4. Quarantine until proven. SharedScalar<T>/OpaqueBytes<N> (MaybeUninit, no safe reads) remain the representation for anything without a decoded reader. Promotion to a real typed field requires instruction-exact evidence, as practiced since A.105.
  5. Reentrancy is stated, not implied. Each piece of shared state carries an access discipline tag: irq-local, hif-task, msg-passing, or hw-table. Mixed access requires a critical section or ownership handoff.

3.2 Three ownership classes for DTCM cells

// Class HW-TABLE: loader-initialized, runtime read-only in practice.
// Typed, const-accessible, no interior mutability exposed.
static COPY_IMAGE: InitializedVendorImage;          // inside DTCM_STATE

// Class SINGLE-OWNER: one execution context owns it; others post events.
struct TxQueueState { /* cursors, retry counters */ }

// Class MSG-PASSING: producer fills a slot, hands over an index token;
// consumer invalidates it. No lock needed if indices are per-direction.
struct PacketSlot { len: u16, flags: u16 }           // packet_ram arena

Rules:

  • A context may hold & of any cell but &mut only under its discipline tag (single owner, or inside a critical section).
  • Cross-context handoff uses index tokens (SlotId(u16)) into fixed arenas (packet_ram, internal context pool). Tokens are Copy; the arena owns the storage. This mirrors what the vendor already does (free-list head + 3-record pool) and maps cleanly onto Rust ownership without unsafe sharing beyond the arena internals.
  • IRQs never spin. They set event bits (existing pattern: bit-set in status words) and return; the HIF task drains them.

3.3 Type-level toolkit (all inside dtcm.rs)

/// Checked address (exists today).
pub struct DtcmAddress(u32);

/// NEW: volatile cell handle replacing raw *mut escapes.
#[repr(transparent)]
pub struct Cell<'a, T> { addr: DtcmAddress, _lt: &'a Disjointness, _t: PhantomData<*mut T> }
impl Cell<'_, T> {
    pub fn read_volatile(&self) -> T;
    pub fn write_volatile(&self, v: T);
}

/// NEW: proof token that interrupts are masked (PRIMASK set) on single core.
pub struct CriticalSection<'a> { _not_send: PhantomData<&'a ()> }

/// NEW: arena slot token for packet_ram / context pool.
#[derive(Copy, Clone)] pub struct SlotId(u16);

The lifetime on Cell is not about DTCM persistence (it is 'static) but about lease discipline: a &mut-style lease is borrowed from a context token and NLL ends it at scope exit, making stale writes a borrow error instead of a review finding.

Dependency rule, mechanically checked: only dtcm/* may contain link_section, linker-symbol externs, addr_of_mut! into DTCM, or DtcmAddress::cast_mut. The existing checker family is the enforcement vehicle: one more script walks src/ and fails on forbidden forms outside dtcm/.

5. Migration plan

PhaseContentExit criterion
P0 done Exact layout, typed records, per-interval drift gates, pointer audit. A.121; ELF identity held throughout.
P1 Pointer confinement: move all *mut accessors behind dtcm::contexts/copy_tables; add the forbidden-forms walker to check.sh.No cast_mut/addr_of_mut! outside dtcm/; all suites green.
P2 Introduce arch::volatile::Cell and CriticalSection; convert callers mechanically (read/write pairs become cell calls). No behavior change. ELF still identical; host tests deterministic.
P3 Stack-first refactor of tx/: descriptor builders become pure functions returning values; only final publication touches cells. Split tx.rs. Descriptor build covered by host unit tests on plain structs.
P4 Optionally port vendor debug console and WSM exception indication using the documented tables (A.119/A.120 docs are the reference).New modules, no DTCM growth.

6. Open risks

  • Writer closure. Any P2/P3 conversion assumes the ported reader list is complete. An unknown IRQ writer to a converted field would see volatile accesses either way, so risk is bounded, but ordering assumptions could differ. Mitigation: keep drift gates running against the parent binary each slice.
  • Init order. MaybeUninit means first-touch correctness rests on loader COPY plus explicit zeroing. P1 must preserve the existing zeroing range exactly.
  • Host-test fidelity. Process-local backing (zeroed() off-target) must keep mirroring target behavior; the existing dual-path pattern stays.
  • Single-core assumption. CriticalSection via PRIMASK is valid only while FIQ masking semantics match the vendor's (FIQ is not masked by PRIMASK on ARM9); verify against vendor entry stubs before relying on it for FIQ-shared cells.
